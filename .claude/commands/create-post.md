# Create Post - Создание постов для Telegram-канала

Создание и публикация постов в канал @dunningkrugereffect в стиле автора.

## Workflow

### 1. Подготовка

Прочитать несколько последних постов для контекста:

```bash
ls -t content/posts/ | head -5
```

Затем прочитать эти файлы, чтобы понять актуальную тематику и тон.

Стиль канала описан в `CLAUDE.md` (загружается автоматически).

### 2. Создание черновика

Написать черновик поста согласно стилю:
- От первого лица, неформально
- Короткие абзацы (1-3 предложения)
- Конкретика и примеры
- Ссылки на источники если есть
- Эмодзи минимально и уместно

Сохранить в `content/drafts/{slug}.md` где `{slug}` — короткое описание темы латиницей.

Пример структуры черновика:

```markdown
---
draft: true
topic: "мой-топик"
created: 2026-02-12
---

Текст черновика поста...
```

### 3. Review

Показать черновик пользователю:
- Прочитать файл черновика
- Вывести текст для review
- Спросить подтверждение на публикацию

Если нужны правки — внести изменения в черновик.

### 4. Публикация

После подтверждения пользователя:

```
send_message(chat_id="dunningkrugereffect", message=<текст_поста>)
```

Инструмент вернёт информацию о опубликованном сообщении, включая ID.

### 5. Сохранение

После успешной публикации:

1. Получить ID опубликованного сообщения из ответа `send_message`
2. Получить точную дату/время публикации
3. Создать файл в `content/posts/` с именем `YYYY-MM-DD-{ID}.md`
4. Скопировать текст из черновика с обновлённым frontmatter:

```markdown
---
id: 110
date: 2026-02-12T14:30:00+00:00
channel: dunningkrugereffect
has_media: false
---

Текст поста...
```

5. Удалить или переместить черновик из `content/drafts/`

## Примеры использования

### Короткий пост (заметка)

**User**: "Напиши пост про новый релиз Python 3.13"

**Action**:
1. Прочитать последние 3-5 постов
2. Написать черновик ~100 слов в стиле канала
3. Показать пользователю
4. После подтверждения — опубликовать — сохранить

### Длинный аналитический пост

**User**: "Напиши про когнитивные искажения в найме"

**Action**:
1. Прочитать похожие посты из архива (2017-2025)
2. Написать черновик 400-600 слов
3. Структурировать с подзаголовками или списками
4. Review — публикация — сохранение

### Пост с медиа

**User**: "Опубликуй эту фотографию с подписью про путешествие"

**Action**:
1. Написать черновик подписи
2. Review
3. Опубликовать (пока текст; медиа отдельно через MCP)
4. Сохранить с `has_media: true` и `media_file: media/{ID}.jpg`

**Примечание**: Загрузка медиа через MCP может иметь технические сложности. Сначала публикуйте текст, медиа — отдельным шагом.

## Чеклист перед публикацией

- [ ] Прочитаны последние посты для контекста
- [ ] Черновик написан в стиле канала (от первого лица, неформально)
- [ ] Короткие абзацы с "воздухом"
- [ ] Ссылки на источники добавлены
- [ ] Эмодзи только если уместно
- [ ] Пользователь подтвердил публикацию
- [ ] Пост опубликован через `send_message`
- [ ] MD-файл сохранён в `content/posts/` с правильным frontmatter

## Обработка ошибок

**Ошибка публикации**: Если `send_message` вернул ошибку, сообщить пользователю и НЕ создавать файл в `content/posts/`.

**Черновик потерян**: Восстановить из истории или запросить повторное написание.

**Неправильный ID**: Если ID не получен, использовать временный filename `YYYY-MM-DD-draft-{slug}.md` и предупредить пользователя.

## Важно

- Всегда показывать черновик пользователю перед публикацией
- Не публиковать автоматически без подтверждения
- Сохранять опубликованные посты в `content/posts/` для истории
- Контент на русском, комментарии в коде на английском
