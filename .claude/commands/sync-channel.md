# Sync Channel - Синхронизация канала

Подтягивание новых сообщений из канала @dunningkrugereffect и сохранение их локально.

## Workflow

### 1. Определить последний сохранённый пост

```bash
ls -t content/posts/ | head -1
```

Прочитать frontmatter файла чтобы получить последний ID:

```markdown
---
id: 109
date: 2025-09-24 05:34:43+00:00
...
```

### 2. Получить новые сообщения

Использовать Telegram MCP для получения истории:

```
list_messages(chat_id="dunningkrugereffect", limit=50)
```

или

```
get_history(chat_id="dunningkrugereffect", limit=50)
```

Эти инструменты вернут список сообщений начиная с самых новых.

### 3. Фильтровать новые

Обработать только сообщения с ID больше последнего сохранённого.

Например, если последний сохранённый ID = 109, обрабатывать только 110, 111, 112 и т.д.

### 4. Для каждого нового сообщения

#### 4.1 Проверить наличие медиа

```
get_media_info(chat_id="dunningkrugereffect", message_id=<ID>)
```

Если медиа найдено, сохранить информацию о нём.

#### 4.2 Скачать медиа (если есть)

```
download_media(
  chat_id="dunningkrugereffect",
  message_id=<ID>,
  file_path="<ID>.ext"
)
```

**Важно**: MCP может скачивать только в корень workspace. После скачивания переместить файл:

```bash
mv <ID>.ext content/media/<ID>.ext
```

**Примечание**: Скачивание медиа может иметь технические проблемы. Если не получается, сохранить пост с `has_media: true` и отметить, что медиа нужно скачать вручную.

#### 4.3 Сохранить MD-файл

Формат filename: `YYYY-MM-DD-{ID}.md`

Frontmatter:

```markdown
---
id: 110
date: 2026-02-12T14:30:00+00:00
channel: dunningkrugereffect
has_media: false  # или true если есть медиа
media_file: media/110.jpg  # только если has_media: true
views: 0  # опционально
---

Текст сообщения...
```

Для сообщений без текста (только медиа):

```markdown
---
id: 111
date: 2026-02-12T15:00:00+00:00
channel: dunningkrugereffect
has_media: true
media_file: media/111.mp4
---

*[Медиа]*
```

### 5. Отчёт

После завершения синхронизации показать пользователю:
- Сколько новых сообщений найдено
- Сколько сохранено
- Сколько имеют медиа
- Список ID новых сообщений

## Примеры использования

### Обычная синхронизация

**User**: "Подтяни новые посты из канала"

**Action**:
1. Определить последний ID (например, 109)
2. Получить историю канала (limit=50)
3. Фильтровать сообщения > 109
4. Для каждого:
   - Проверить медиа
   - Скачать медиа если есть
   - Сохранить MD-файл
5. Показать отчёт: "Синхронизировано 3 новых поста: 110, 111, 112"

### Первая синхронизация (уже выполнена)

Если `content/posts/` пустая, загрузить полную историю:

```
get_history(chat_id="dunningkrugereffect", limit=100)
```

**Примечание**: Первая синхронизация уже выполнена, в проекте сохранено 100 сообщений (ID 9-109).

### Синхронизация после длительного перерыва

Если пропущено много сообщений, возможно понадобится несколько запросов:

```
list_messages(chat_id="dunningkrugereffect", limit=100)
```

Если найдено 100 сообщений и есть ещё старые, повторить запрос для следующей пачки.

## Обработка медиа

### Типы медиа

- **Фото**: `.jpg`, `.png`
- **Видео**: `.mp4`, `.mov`
- **Документы**: `.pdf`, `.docx` и др.
- **Голосовые**: `.ogg`

### Расширение файла

Определить расширение из `media_info`:
- `MessageMediaPhoto` → `.jpg`
- `MessageMediaDocument` → из `mime_type` или `file_name`
  - `video/mp4` → `.mp4`
  - `application/pdf` → `.pdf`

### Fallback если скачивание не работает

Если `download_media` падает с ошибкой:
1. Сохранить пост с `has_media: true`
2. Добавить комментарий в файл:
   ```markdown
   <!-- Media download failed, manual download required -->
   ```
3. Сообщить пользователю список сообщений с проблемами

## Чеклист синхронизации

- [ ] Определён последний сохранённый ID
- [ ] Получена история канала
- [ ] Отфильтрованы только новые сообщения
- [ ] Для каждого нового:
  - [ ] Проверено наличие медиа
  - [ ] Скачано медиа (если есть и возможно)
  - [ ] Сохранён MD-файл с правильным frontmatter
- [ ] Показан отчёт пользователю

## Важно

- Всегда сохранять даты в формате ISO с timezone
- Не перезаписывать существующие файлы
- Если ID уже существует, пропускать (не обновлять)
- Медиа сохранять с ID в имени файла: `{ID}.ext`
- После синхронизации можно сделать git commit с изменениями
