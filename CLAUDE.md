### Формат MD-файлов постов

```markdown
---
id: 108
date: 2025-09-24 05:34:43+00:00
channel: dunningkrugereffect
has_media: false
media_file: media/108.jpg  # только если has_media: true
views: 180                 # опционально
---

Текст сообщения...
```

### Формат MD-файлов черновиков

```markdown
---
slug: my-topic-slug
title: "Заголовок (опционально)"
channel: dunningkrugereffect
has_media: false
---

Текст черновика...
```

Фактический формат — см. `content/drafts/no-more-apps-02-food.md`. В `.claude/commands/create-post.md` указан устаревший шаблон (`draft: true`, `topic:`, `created:`) — **не использовать**.

### Workflow публикации

1. Создать черновик в `content/drafts/{slug}.md`
2. Показать пользователю для review
3. После подтверждения — опубликовать через `send_message` в канал
4. Получить ID опубликованного сообщения
5. Переместить из `drafts/` в `content/posts/` с именем `YYYY-MM-DD-{ID}.md`

Подробнее: `/project:create-post`

### Особенности telegram-mcp

- Запущен в Docker-контейнере (`~/src/personal/telegram-mcp/docker-compose.yml`) **без volume-mount** → `send_file` не видит файлы хоста, возвращает `File not found` на любой путь. **Медиа к постам пользователь прикрепляет вручную** через Telegram-приложение.
- `send_message` **не возвращает ID** опубликованного сообщения — после публикации звать `get_history(chat_id, limit=1)` для получения ID.
- Нет поддержки media group / альбомов — каждый файл = отдельное сообщение в канале, со своим message_id.
- `caption` у `send_file` ограничен 1024 символами — длинные посты всегда публикуем отдельным `send_message`, потом медиа.

### Форматирование

**Структура постов:**
- Короткие абзацы (1-3 предложения)
- Пустые строки между абзацами для "воздуха"
- Маркированные списки для перечислений
- Иногда нумерованные списки для пошаговых инструкций

**Ссылки:**
- Всегда даются ссылки на источники
- Часто прямые URL без markdown-форматирования
- Telegram-ссылки на другие каналы (`https://t.me/...`)

**Цитаты:**
- Прямые цитаты из книг/статей выделяются
- Иногда используется `> ` для цитирования
- Примеры: "— Дрессировка без наказания"

**Эмодзи:**
- Используются минимально и уместно
- Чаще в контексте путешествий
- Не злоупотребление — макс 1-2 на пост

**Длина:**
- От одного предложения до 500+ слов
- Короткие заметки: "LOL", "Приехали в Крым"
- Средние посты: 100-200 слов (обзоры, новости)
- Длинные аналитические: 400-800 слов (менеджмент, когнитивные искажения)

**Единицы измерения:**
- Метрические: см, м, км, °C, литры, кг. Автор в РФ.
- Не использовать: дюймы, мили, фаренгейты (кроме случаев, когда это часть маркировки/названия модели — `7" headlight`, `180 мм`).

### Особенности контента

**Личный опыт как основа:**
- "Я начал перечитывать..."
- "2 месяца отпользовал iPhone X после iPhone 6..."
- "Лет 6 назад во Flatstack мы разрабатывали..."
- Всегда конкретика, а не абстракция

**Экспертные наблюдения:**
- Технические детали (SSL-сертификаты, DNS, API)
- Критический взгляд на индустрию
- Объяснение сложного простым языком
- Честность о своих ошибках

**Рекомендации:**
- Инструменты: Zoom, Anker, esimdb.com, Hetzner
- Книги: "Remote", "Думай медленно, решай быстро"
- Сервисы: Calimoto для треков, tunnelbear для VPN
- Всегда с контекстом применения

**Критика некомпетентности:**
- Роскомнадзор — частая тема критики
- Вскрытие технических ошибок
- Эмоциональная, но аргументированная позиция
- "Мне стыдно, что на мои деньги... содержится вся эта шушера"

## Инструкции для агента

### При создании нового поста:

1. Прочитать несколько последних постов из `content/posts/` для контекста
2. Писать от первого лица, неформально
3. Если технический контент — добавить конкретику и примеры
4. Если личный опыт — быть честным, включая негатив
5. Давать ссылки на источники
6. Короткие абзацы, много воздуха
7. Эмодзи — только если очень уместно
8. Проверить: "Звучит ли это как я?"

**Референсы стиля по темам:**
- Мото-тюнинг: `content/posts/2025-08-07-098.md` — структура «интро → раздел на каждый апгрейд (подзаголовок простой строкой, без markdown `**жирного**`) → итог-философия».
- Мото-путешествия: `content/posts/2025-09-1*.md` (серия Крым + Эльбрус).
- Замена приложений на AI-инструменты: `content/posts/2026-03-24-110.md` + серия черновиков `no-more-apps-*`.

Полный workflow: `/project:create-post`

### При синхронизации канала:

1. Определить последний сохраненный пост по файлам в `content/posts/`
2. Получить новые сообщения через `list_messages` или `get_history`
3. Для каждого нового:
   - Сохранить MD-файл с frontmatter
   - Проверить наличие медиа через `get_media_info`
   - Скачать медиа если есть (примечание: возможны проблемы с путями)

Полный workflow: `/project:sync-channel`

### Общие принципы:

- Контент на русском, code comments на английском
- Git commits на английском
- Не создавать лишних файлов/директорий
- Сохранять существующую структуру проекта
